# 参考驱动的 PPT 制作
## 默认配置
读取 `templates/design-spec.json`。默认高相似度参考、通用表达、分层背景、手写标题与清晰正文、叙事演示、适度编辑、16:9、中文、WPS、课堂演讲、完整设计包。用户明确要求优先；本次授权延续，不重复索取批准。
## 执行顺序
1. 阅读 `references/input-contract.md`，收集参考、内容、受众、时长、页数、WPS 环境。查阅可用工具与依赖；先检查输入文件是否真正可读取。不能读取的图片不要声称已提取颜色。
2. 阅读 `references/reference-analysis.md`。查看每张参考图；对 PPT 读取主题、母版、布局、字体及代表页。输出风格证据与设计参数，区别观察事实和推断。高相似度保留视觉规律，避免直接截取参考文字、标志或整页充当成品。
3. 填写 brief 与 design-spec；列出两到三种有实际区别的设计方案并标推荐。用户已选参数则直接沿用。仅对缺失且影响结果的信息提问，其余标注假设。
4. 阅读 `references/classroom-storytelling.md`，按内容规划逐页标题、学习目标、布局、讲述要点、分钟数、数据来源、交互及动画步骤。不得编造事实。缺失信息标待补充。
5. 默认先确认设计与页纲，再制作封面、正文、复杂信息三种代表页并提供预览。代表页确认后扩展全稿。若用户明确授权直接完成，跳过确认节点。当前包的示例已获直接创建授权。
6. 应用 `references/design-system.md`；按任务设计至少五种版式。修改全局 token 后重新生成全部页面。支持页型：cover、agenda、section、content、compare、process、chart、summary、closing。脚本是可执行起点；若任务需要新构图、公式、图片、复杂图表或视频，扩展脚本，不把不同风格强行套成咖啡主题。
7. 将确认的逐页方案写成 JSON；按 README 命令构建。原始模板优先使用 --template 并保留主题/母版；真实占位符映射需检查后扩展，不承诺任意模板自动重排。
8. 阅读 `references/motion-and-navigation.md` 与 `references/wps-compatibility.md`。优先基础淡化、目录链接及点击顺序；复杂动画不可用时采用连续页揭示，明确交付实现。不要将动画脚本冒充实际动画。
9. 执行 inspect 与 render。逐页看真实渲染预览，检查溢出、对比度、对齐、图表、字体。读取 `references/quality-checklist.md` 完成逐项状态记录。脚本结构检查不能替代人工目视和 WPS 播放。
10. 按 `references/delivery-spec.md` 交付文件、预览和报告，说明尚未验证项。
## 快速入口
完整命令、依赖和扩展边界见 README.md。运行脚本前先验证 JSON。技能本身不主动联网安装依赖、不发布、不发送任何资料。
